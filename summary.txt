Summary: create_pvf_table
=========================

Goal
----
The script automates the creation of a phase volume fraction (PVF) table in
either LibreOffice Writer or LibreOffice Impress. The table is intended to
display, for each tissue or material phase, a colour-coded identifier and its
volume percentage. Producing this table by hand for each dataset is repetitive
and error-prone, so the script takes a CSV file as input and generates the
finished document automatically.


The ODF file format
-------------------
Both .odt (Writer) and .odp (Impress) files are ZIP archives containing XML
files. The main content lives in content.xml, which describes the document
structure, automatic styles, and body text. This means the documents can be
read and written programmatically using Python's standard zipfile and
xml.etree.ElementTree modules, with no dependency on LibreOffice itself.


Approach: modify a template rather than build from scratch
----------------------------------------------------------
Rather than generating the full ODF XML from scratch (which would require
reproducing every border, padding, and style attribute correctly), the script
starts from hand-crafted template files — phasevoltable_empty.odt and
phasevoltable_empty.odt — that already contain the correctly structured table
with the right borders, padding, and cell layout. The script copies the
template ZIP, parses content.xml, makes targeted changes, and writes the
result to a new file.

This keeps the code focused: it only needs to know about the things that
change (cell text), not the full document structure.


XML namespace handling
----------------------
ODF XML uses around 30 XML namespaces. Python's ElementTree represents
element and attribute names as expanded Clark-notation strings, e.g.
{urn:oasis:names:tc:opendocument:xmlns:table:1.0}table-row. Before parsing,
the script registers all known ODF namespace prefixes so that ElementTree
serialises them back with the original short prefixes (table:, style:, fo:,
etc.) rather than invented ns0:, ns1: substitutes that LibreOffice might
reject.


Variable phase count
--------------------
The CSV may contain anywhere from 1 to 8 phase columns. The script fills
only as many rows as the data provides and removes the remaining template
rows, so the output table is always the exact right size.

All formatting — background colours, font, alignment, column widths, and
padding — is defined in the template files and left untouched by the script.


Output naming
-------------
The output file is named table_<stem>.<ext>, where <stem> is the CSV filename
without its extension and <ext> is odt or odp. It is written to the directory
from which the script is called, not to the script's own directory, so it
lands wherever the user is working.
